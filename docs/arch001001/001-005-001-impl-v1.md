## 4. Dependency Rule Check Summary

| Change                       | Dependency Impact                     | Risk |
| ---------------------------- | ------------------------------------- | ---- |
| Remove core re-export        | Breaks `@valfuse-node/core` consumers | High |
| Add shared utilities to core | form→core is now acceptable           | Low  |
| Localization depends on core | localization→core (shared only)       | Low  |
| Yarn enforcement             | None - config only                    | Low  |

### Critical Dependency Rules

1. **NO**: `core → form` (domain logic)
2. **NO**: `form → localization`
3. **NO**: `localization → form`
4. **YES**: `form → core` (only for shared utilities, no domain logic)
5. **YES**: `localization → core` (only for shared utilities)
6. **YES**: `react → form`, `vue → form`
7. **YES**: `react → localization`

## 8. Risk Mitigation

### High Risk Items

#### TASK-001: Remove core re-export

- **Risk**: Breaking existing consumers
- **Mitigation**:
  1. Deprecation notice first (TASK-004)
  2. Migration guide (TASK-011)
  3. Version bump (patch or minor, not major if possible)
  4. Clear CHANGELOG entry

#### TASK-002: Add shared utilities

- **Risk**: Incorrectly placing form-specific logic in core
- **Mitigation**:
  1. Strict audit of what truly belongs in shared
  2. Core has ZERO knowledge of form schema types
  3. Only plain utility functions in shared

### Medium Risk Items

#### TASK-003: Localization depends on core

- **Risk**: Build issues if core isn't built yet
- **Mitigation**: yarn workspace hoisting handles this, but must run `yarn build` in core before localization

## 9. Implementation Commands

### Build Order (for yarn workspace)

```bash
# 1. Build core first (shared utilities)
yarn workspace @valfuse-node/core build

# 2. Build form (depends on core)

# 3. Build others

yarn workspace @valfuse-node/react build
```
