## 2. Executive Summary

### Current State
- Form domain logic correctly located in `packages/form/` ✅
- `packages/core` is architecturally broken — it re-exports all form logic ❌
- No shared utilities exist in `packages/core` ❌
- `packages/localization` has no dependency on `packages/core` ❌
- No yarn engine enforcement ❌
- `packages/form` lacks unit tests ❌

```
react ──→ form ──→ [schema, rules, validation, transformation]
vue   ──→ form
```

## 4. Conflict Resolution

### Conflict 1: Core's Role
**Issue**: User says core is "Orchestration" but current implementation is just a re-export wrapper.

**Resolution**: Core should be kept but repurposed:
- Remove `export * from "@valfuse-node/form"`
- Add shared utilities that both form AND localization use
- Core coordinates between form and localization (orchestration role)

**Why**: User explicitly stated "core sebagai Orchestration" — this is a clear architectural decision.

### Conflict 2: Shared Utilities Definition
**Issue**: No shared utilities currently exist.

**Resolution**:
1. Audit form and localization for common patterns
2. Candidate shared utilities: `t` transformer, error normalization
3. Extract to `packages/core/src/shared/`

**Why**: User requirement states shared utilities go in core, used by form AND localization.

### Conflict 3: Migration Risk vs Architecture Correctness
**Issue**: Removing core's re-export breaks backward compatibility.

**Resolution**: Deprecation strategy:
1. Mark `@valfuse-node/core` as deprecated with warning
2. Document migration path: use `@valfuse-node/form` directly
3. Keep core for orchestration role only

**Why**: Clean architecture takes priority, but we minimize migration pain.

## 6. Recommended Architecture

### Target Package Structure

```
packages/
├── core/                    ← Orchestration + Shared
│   └── src/
│       ├── shared/        ← Utilities used by form AND localization
│       │   ├── transformers.ts   (moved from form/shared/)
│       │   └── index.ts
│       └── public-api.ts  ← Export shared only (NO form re-export)
│
├── form/                   ← Form Domain (unchanged)
│   └── src/
│       ├── schema/         ✅
│       ├── validation/    ✅
│       ├── transformation/ ✅
│       ├── rules/         ✅
│       ├── errors/         ✅
│       ├── shared/        ← Transform utilities (depends on core)
│       ├── types/         ✅
│       ├── state/         ✅
│       └── methods/       ✅
│
├── localization/           ← i18n/l10n (depends on core for shared)
│   └── src/
│       └── ... (unchanged)
│
├── react/                  ← React adapter (depends on form + localization)
│   └── src/...
│
└── vue/                    ← Vue adapter (depends on form)
    └── src/...
```

### Dependency Direction (Target)
```
react ──→ form ──→ [schema, rules, validation, transformation]
vue   ──→ form
localization ──→ core (shared utilities)
core ──→ (nothing — orchestration coordination only)
```
