## 2. Project Overview

### Current Package Structure

```
packages/
├── core/           ← Orchestration layer (re-exports form)
├── form/           ← Form domain (schema, validation, rules, transformation)
├── react/          ← React adapter
├── vue/            ← Vue adapter  
├── localization/   ← CLI + browser runtime
└── examples/       ← Example applications
```

### Current Dependency Graph

```
react ──→ core ──→ form
vue   ──→ core ──→ form
localization ──→ (standalone, no core dependency currently)
```

## 3. User Requirements

| # | Requirement |
|---|-------------|
| 1 | Schema, validateSchema, transformValues, rules MUST be in `packages/form/` |
| 2 | `packages/core` is Orchestration only — coordinates form and localization |
| 3 | `packages/core` should have NO schema, validateSchema, or rules |
| 4 | Shared utilities used by BOTH form and localization go in `packages/core` |
| 5 | Localization depends on core for shared utilities only |
| 6 | Use **yarn only** — not npm |

## 5. Analysis: Current vs Target Architecture

### Current State Assessment

| Aspect | Status | Notes |
|--------|--------|-------|
| Form domain in `packages/form/` | ✅ Correct | schema, validation, rules, transformation all in form |
| `packages/core` orchestration | ⚠️ Partial | Currently just re-exports form; no actual orchestration |
| Shared utilities in core | ❌ Missing | No shared utilities defined yet |
| Localization depends on core | ❌ Not done | localization has no dependency on core |
| Yarn only | ⚠️ Unknown | Need to verify package manager usage |

### Target Architecture (from User Requirements)

```
packages/
├── core/           ← Orchestration layer
│   └── shared/     ← Utilities used by form AND localization
├── form/           ← Form domain
│   ├── schema/
│   ├── validation/
│   ├── transformation/
│   ├── rules/
│   ├── errors/
│   ├── shared/
│   ├── types/
│   ├── state/
│   └── methods/
├── react/          ← React adapter (depends on form, localization)
├── vue/            ← Vue adapter (depends on form)
└── localization/  ← CLI + browser (depends on core shared utilities)
```

## 6. Gap Analysis

### Must Fix

| # | Gap | Severity | Description |
|---|-----|----------|-------------|
| 1 | Core has no actual orchestration | High | Core just re-exports form; no coordination logic |
| 2 | No shared utilities in core | High | Shared utilities (if any) not extracted to core |
| 3 | Localization doesn't depend on core | High | No architectural link between localization and core |
| 4 | Package manager enforcement | Medium | Need to ensure yarn-only policy |

### Should Fix

| # | Gap | Severity | Description |
|---|-----|----------|-------------|
| 5 | Core could expose orchestration API | Medium | If core does orchestration, it needs public API |
| 6 | React localization coupling | Medium | React package has localization code; may need refactoring |

## 7. Technical Debt

| Debt | Impact | Severity | Suggested Improvement |
|------|--------|----------|----------------------|
| Core is just a re-export wrapper | Low (works but adds no value) | Medium | Either remove core or give it real orchestration role |
| Localization not connected to core | Architecture inconsistency | High | Add core dependency to localization package |
| No yarn.lock enforcement | Potential npm usage | Medium | Add .npmrc or package.json engines field |

---

## 8. Risk Areas

| Risk | Level | Mitigation |
|------|-------|------------|
| Breaking changes if core removed | Medium | Deprecation period with warnings |
| Yarn vs npm confusion | Low | Add engines field to package.json |
