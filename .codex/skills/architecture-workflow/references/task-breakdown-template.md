## Split Rules
- Split slicing and integration if UI layout can be reviewed before data/API is ready.
- Split domain/use case work from infrastructure adapters if both are non-trivial.
- Split testing tasks when they require separate fixtures, environment, or QA flow.
- Split documentation if architecture decisions need ADRs.
